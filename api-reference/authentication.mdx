Every request to the Built Block API must be authenticated with an API key. The API uses bearer token authentication — you include your key in the `Authorization` header of each request. There are no sessions or cookies involved, making it straightforward to use from any HTTP client or language.

## Generating an API Key

To create an API key, navigate to your Built Block dashboard and follow these steps:

<Steps>
  <Step title="Open Settings">
    Click your account avatar in the top-right corner of the dashboard, then select **Settings** from the dropdown menu.
  </Step>
  <Step title="Go to API Keys">
    In the Settings sidebar, click **API Keys** under the Developer section.
  </Step>
  <Step title="Create a new key">
    Click **New API Key**, give it a descriptive name (e.g., `production-backend` or `ci-pipeline`), and select the appropriate scope.
  </Step>
  <Step title="Copy your key">
    Your key is displayed **once** immediately after creation. Copy it and store it securely — you will not be able to view it again.
  </Step>
</Steps>

<Warning>
  If you lose an API key, you must revoke it and generate a new one. Built Block cannot recover or display a key after you leave the creation screen.
</Warning>

## Making Authenticated Requests

Pass your API key as a bearer token in the `Authorization` header on every request:

```http
Authorization: Bearer YOUR_API_KEY
```

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.builtblock.com/v1/projects \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json"
```

```javascript JavaScript (fetch)
const response = await fetch("https://api.builtblock.com/v1/projects", {
  method: "GET",
  headers: {
    "Authorization": `Bearer ${process.env.BUILTBLOCK_API_KEY}`,
    "Content-Type": "application/json",
  },
});

const data = await response.json();
console.log(data);
```

```python Python (requests)
import os
import requests

headers = {
    "Authorization": f"Bearer {os.environ['BUILTBLOCK_API_KEY']}",
    "Content-Type": "application/json",
}

response = requests.get(
    "https://api.builtblock.com/v1/projects",
    headers=headers,
)

data = response.json()
print(data)
```

</CodeGroup>

## API Key Scopes

When you create a key, you assign it one of two permission scopes that control what operations it can perform:

| Scope          | Description                                                                 |
|----------------|-----------------------------------------------------------------------------|
| `read-only`    | Allows `GET` requests only. The key can read resources but cannot create, update, or delete them. |
| `read-write`   | Allows all methods: `GET`, `POST`, `PATCH`, and `DELETE`. The key can read and modify all resources. |

<Note>
  Use the narrowest scope that satisfies your use case. For dashboards, analytics pipelines, or any integration that only reads data, prefer `read-only` keys to reduce the blast radius of an accidental leak.
</Note>

Attempting to perform a write operation with a `read-only` key returns a `403 Forbidden` error.

## Revoking a Key

To revoke a key, return to **Settings → API Keys** in the dashboard, locate the key by name, and click **Revoke**. Revocation is immediate — any in-flight requests using the revoked key will fail with `401 Unauthorized`.

## Security Best Practices

<Warning>
  Never commit API keys to source control. Treat them with the same care as passwords. If a key is accidentally exposed in a public repository, revoke it immediately.
</Warning>

<Tip>
  Store API keys in environment variables (e.g., `BUILTBLOCK_API_KEY`) and load them at runtime. Use a secrets manager such as AWS Secrets Manager, HashiCorp Vault, or your CI/CD platform's built-in secrets store for production workloads.
</Tip>

Follow these practices to keep your API keys secure:

- **One key per service** — create a separate key for each application or environment so you can revoke access to a single service without affecting others.
- **Rotate keys periodically** — set a reminder to rotate long-lived keys on a schedule appropriate for your security policy.
- **Audit key usage** — review the last-used timestamp for each key in the dashboard to identify unused keys that can be safely revoked.
- **Restrict access** — if your infrastructure allows it, restrict outbound requests to the Built Block API to specific services or IP ranges.
