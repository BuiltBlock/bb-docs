The Account API is at `https://api.builtblock.com`. Use it to read diagnosis for one customer, list the customer book, resolve a name or domain to an account id, push one item, or set lifecycle and the date they became a customer.

Create a key on the **API** page in the app. Session cookies are rejected. MCP uses sign-in, not this key. See [Authentication](/api-reference/authentication).

This reference matches the Account API as of October 13, 2026. When the API changes, this spec is updated with it.

## Endpoints

| Method | Path | What it does |
| --- | --- | --- |
| `GET` | [`/v1/accounts`](/api-reference/executive-customer-book) | The customer book. Defaults to customers. Returns up to 500 rows. |
| `POST` | [`/v1/accounts`](/api-reference/push-account-data) | Push an account, an optional person, and one item, then queue processing |
| `GET` | [`/v1/accounts/resolve`](/api-reference/resolve-name-or-domain-to-an-account-id) | Turn an exact name or domain into an account id |
| `GET` | [`/v1/accounts/{id}/state`](/api-reference/one-customer-diagnosis) | One account: diagnosis, summary, outcomes, use cases, people, timeline, and usage |
| `PATCH` | [`/v1/accounts/{id}`](/api-reference/set-lifecycle-or-customer-date) | Set lifecycle, `customer_since`, or both |

The account id in these paths is the BuiltBlock id. It is not a HubSpot id. Resolve a name or domain first when you do not have the id yet.

People in the account payload do not include email addresses.

A HubSpot lifecycle, or a won deal, still decides the relationship. `PATCH` reports `lifecycle_applied: false` when that existing fact was kept.
