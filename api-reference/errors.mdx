A failed request returns JSON with `error` and `code`.

```json
{
  "error": "No account matched that domain.",
  "code": "not_found"
}
```

## Codes

| Code | Typical status | What to do |
| --- | --- | --- |
| `unauthorized` | 401 | Send a valid API key. See [Authentication](/api-reference/authentication). |
| `no_tenant_map` | 403 | The key is valid, but it is not linked to an organization. Create a new key from the **API** page. |
| `not_found` | 404 | Nothing matched. Check the name, domain, or account id. |
| `account_not_found` | 404 | That account id is not in your organization. |
| `ambiguous` | 409 | More than one account matched. Use the account id, or a more specific name or domain. |
| `bad_query` | 400 | The body or query is missing a required field, or it includes the wrong combination of fields. |
| `invalid_relationship` | 400 | `relationship` must be `prospect`, `customer`, `former`, or `unknown`. |
| `rate_limited` | 429 | Wait for the number of seconds in `Retry-After`, then retry. |
| `internal_error` | 500 | Retry later. Contact [support@builtblock.com](mailto:support@builtblock.com) if it continues. |

`POST /v1/accounts` returns 400 when the item is invalid, or when both the account and the person are missing. It returns 404 for an unknown account id and 409 when more than one account matches.

`PATCH /v1/accounts/{id}` returns 400 when the body has neither `lifecycle` nor `customer_since`.

`GET /v1/accounts/resolve` needs exactly one of `name` or `domain`.
