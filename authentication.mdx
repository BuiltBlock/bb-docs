Every request to the Built Block REST API must include a valid API key. Built Block uses **Bearer token authentication** — you generate a key in the dashboard and attach it to each request via the `Authorization` HTTP header. This page explains how to find your keys, format the header correctly, and troubleshoot the most common authentication errors.

## Finding your API keys

API keys are managed under your account settings, not at the project level, so a single key can authenticate requests across all of your projects.

1. Sign in to [app.builtblock.com](https://app.builtblock.com) and click your avatar in the top-right corner.
2. Select **Settings** from the dropdown.
3. Open the **API Keys** tab.
4. Click **Generate new key**, enter a descriptive label (for example, `production-server` or `ci-pipeline`), and click **Create**.
5. **Copy the key immediately.** Built Block displays the full key only once. If you lose it, you must revoke the old key and create a new one.

<Note>
  You can create multiple API keys — for example, one per environment or service. Each key appears in the **API Keys** tab with its label, creation date, and last-used timestamp so you can audit usage.
</Note>

## Passing the Authorization header

Include your API key in every request as a Bearer token in the `Authorization` header.

<ParamField header="Authorization" type="string" required>
  The authentication credential for the request. Format: `Bearer YOUR_API_KEY`. The word `Bearer` is case-sensitive and must be followed by a single space and your API key.
</ParamField>

<CodeGroup>

```bash curl
curl -X GET https://api.builtblock.com/v1/projects \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

```javascript JavaScript (fetch)
const apiKey = process.env.BUILTBLOCK_API_KEY; // never hard-code secrets

const response = await fetch("https://api.builtblock.com/v1/projects", {
  method: "GET",
  headers: {
    "Authorization": `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
});

if (!response.ok) {
  throw new Error(`Request failed: ${response.status} ${response.statusText}`);
}

const data = await response.json();
console.log(data);
```

</CodeGroup>

<Tip>
  Store your API key in an environment variable (such as `BUILTBLOCK_API_KEY`) rather than hard-coding it in your source files. This keeps secrets out of version control and makes key rotation straightforward.
</Tip>

## Authentication error codes

When a request fails authentication or authorization, Built Block returns a standard error body alongside the relevant HTTP status code.

### 401 Unauthorized

A `401` response means the API could not verify your identity. Common causes:

- The `Authorization` header is missing entirely.
- The header value is malformed (for example, missing the `Bearer ` prefix, or extra whitespace).
- The API key has been revoked or does not exist.

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing or invalid Authorization header. Provide a valid Bearer token."
  }
}
```

**Resolution:** Confirm that the `Authorization` header is present and formatted as `Bearer YOUR_API_KEY`. Re-copy the key from **Settings > API Keys** to rule out a transcription error.

### 403 Forbidden

A `403` response means Built Block recognized your API key but the key does not have permission to perform the requested action.

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "Your API key does not have permission to perform this action."
  }
}
```

**Resolution:** Check whether the key you are using was created with a restricted scope, or whether your account plan includes the endpoint you are calling. Upgrade your plan or generate a key with the appropriate permissions from **Settings > API Keys**.

<Warning>
  Do not share a single high-privilege API key across all environments. If a broadly permissioned key is compromised, an attacker can access every project and workflow under your account. Use separate, least-privilege keys for each environment or service.
</Warning>

## Rotating and revoking keys

You should rotate API keys periodically and immediately whenever a key may have been exposed.

1. Go to **Settings > API Keys** in the dashboard.
2. Click the **Revoke** button next to the key you want to retire.
3. Generate a new key, update your environment variable or secret manager, and deploy the change.
4. Verify that your services are responding correctly before closing the rotation window.

<Note>
  Revoking a key is immediate and permanent. Any in-flight requests using the revoked key will start returning `401` errors as soon as the revocation takes effect.
</Note>
